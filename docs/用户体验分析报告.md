# AI小说创作系统 — 用户行为分析与体验洞察报告

> 基于产品文档 v2.0、架构文档、智能系统集成方案，结合 `ai-novel-studio` 当前代码实现
> 分析日期：2026-05-05

---

## 一、用户画像与角色定义

### 1.1 目标用户分层

| 层级 | 用户类型 | 核心需求 | 技术素养 | 创作能力 |
|------|---------|---------|---------|---------|
| **P0** | 网文作者（个人） | 从灵感→百万字完本的全流程工具 | 低-中 | 中-高 |
| **P1** | 小说工作室/创作团队 | 多项目批量生产、质量统一 | 中 | 中 |
| **P2** | 小说策划/编辑 | 审核、质量控制、商业化评估 | 中 | 高 |
| **P3** | 新手作者/跨界作者 | 灵感激发、快速上手、降低门槛 | 低 | 低-中 |

### 1.2 典型用户场景

**场景 A — 老手作者（主力用户）**
> 王哥，30岁，写了3年网文，目前在番茄连载一部都市脑洞文，日更6000字。
> 痛点：构思大纲和章纲消耗大量时间，连续性强但经常忘角色设定和伏笔。
> 目标：用AI加速设定→大纲→章纲→正文的流水线，把精力放在关键剧情转折上。

**场景 B — 工作室主理人**
> 李姐，运营一个5人小工作室，同时维护3部连载小说。
> 痛点：作者水平参差，质量不统一，伏笔和Hook经常遗漏。
> 目标：标准化创作流程，批量审核，质量门禁。

**场景 C — 网文新手**
> 小明，大一学生，想写但不知道怎么开头。
> 痛点：无从下手，设定太复杂，容易弃坑。
> 目标：灵感模式快速生成开局，AI引导走完完整流程。

## 二、用户主流程体验分析

### 2.1 用户旅程总览

```
注册/登录 → 新建项目 → 世界设定 → 小说总纲 → 卷纲管理 → 章纲管理 
→ 章节生成(七步工作流) → 审核修订 → 入库导出
```

这是产品文档定义的「完整创作闭环」。但我对照当前代码，发现以下关键问题：

### 2.2 各阶段体验细节

#### 阶段 1：登录 → 工作台

| 维度 | 现状 | 评估 |
|------|------|------|
| 入口体验 | 渐变色登录页，简洁清晰 | ✅ 良好 |
| 注册流程 | 仅支持登录，无注册页面 | ⚠️ 缺失 |
| 工作台Dashboard | 4个统计卡片 + "快速开始"占位 | ❌ 几乎无信息量 |
| 导航结构 | 仅4个一级菜单，项目内功能入口藏得深 | ⚠️ 可发现性差 |

**行为洞察：**
- 用户首次登录后的「空状态」——Dashboard只有4个零值统计 + 一段空文本，没有引导用户"下一步干嘛"。
- 项目列表、项目内部的世界设定/卷纲/章纲等入口**要点击两次才能到达**（项目列表→项目详情→Tabs），操作路径偏长。
- Dashboard缺少：最近编辑的项目、待办任务、AI调用统计、创作进度提示。

#### 阶段 2：新建项目

| 维度 | 现状 | 评估 |
|------|------|------|
| 创建表单 | 名称、类型、视角、目标字数、描述 | ✅ 信息适当 |
| 创建后跳转 | 跳转到项目详情页(空的Tabs界面) | ❌ 没有引导进入下一步 |

**核心痛点：**
- 创建项目后直接进入空白的Tabs页面，用户会困惑"该先点哪个？"。
- 产品文档定义了热榜分析生成和用户输入生成两种世界设定模式，但当前项目创建表单中**完全没有体现**。
- 缺失「创作向导」或「项目模板」——新手不知道世界设定和大纲的关系。

#### 阶段 3：世界设定

| 维度 | 现状 | 评估 |
|------|------|------|
| 输入项完整性 | 基础设定+冲突目标+爽点Hook 3个Tab | ⚠️ 缺失金手指/职业体系/组织体系/禁忌设定等 |
| AI生成按钮 | 有"AI生成设定"按钮 | ⚠️ 目前是空的(TODO) |
| 保存按钮 | 有"保存设定" | ✅ |
| 产品文档对标 | 文档定义14个输出项，代码仅实现约7个输入字段 | ❌ 差距大 |

**行为洞察：**
- 世界设定是后续所有创作的上游数据源，但当前输入字段远少于产品文档定义。
- "AI生成设定"按钮点了没反应（TODO），这恰恰是用户最期待的核心功能之一。
- 缺少与「热榜分析」的连接——产品文档的热榜分析→自动生成世界设定的链路没有打通。

#### 阶段 4：小说总纲 → 卷纲 → 章纲

| 流程节点 | 现状 | 评估 |
|---------|------|------|
| 小说总纲 | 纯文本编辑框，无AI生成 | ❌ 仅为富文本编辑器 |
| 卷纲管理 | 仅CRUD，无AI批量生成 | ❌ 缺失核心功能 |
| 章纲管理 | 代码中未实现章节大纲页面 | ❌ 完全缺失 |
| 产品文档对标 | 卷纲14项输出、章纲18个字段 | ❌ 无对应 |

**核心问题：**
- 小说总纲理应是产品文档定义的多结构化输出（主线/核心冲突/阶段目标等），但当前只是一个空白TextArea。
- 卷纲管理缺少：生成模式(全新/续写)、生成范围、每卷章节数、每章字数、DeepEditor检查、批量后台运行等。
- **章纲管理页面完全不存在**——但章纲是"七步工作流"第一步骤Planner的关键输入。

#### 阶段 5：章节生成（核心体验）

| 维度 | 现状 | 评估 |
|------|------|------|
| 编辑器 | TextArea富文本编辑 | ✅ 可用 |
| 创作模式 | 快速/标准/严格 | ✅ UI已设计 |
| 七步流程启动 | 有确认弹窗 | ⚠️ 当前启动后无实际效果 |
| 模拟生成 | 有硬编码的示例内容 | ⚠️ 仅为demo演示 |
| 实时进度 | 产品文档定义SSE推送 | ❌ 未连接实际SSE |
| AI去味模式 | 产品文档定义29种 | ❌ 代码未实现 |
| 审核结果展示 | 未实现 | ❌ |

**关键行为观察：**
- `ChapterEditor.tsx` 是用户**停留时间最长的页面**，但目前仅是一个简单的TextArea + 几个按钮。
- 生成设置弹窗（Modal）包含创作模式、字数、风格、视角——这是对的，但缺少：
  - 是否启用Planner（知识库约束）
  - 审核强度（轻度/标准/严格）
  - AI去味强度
  - Hook强制要求
- "启动创作流程"按钮是高频操作，但当前无实际后端响应，用户在等待后会产生挫败感。
- 编辑器缺少：**版本对比**、**修订历史**、**审核面板**——而这些产品文档都定义了。

#### 阶段 6：工作流监控

| 维度 | 现状 | 评估 |
|------|------|------|
| 工作流列表 | 有表格UI | ✅ 可用 |
| 进度展示 | 有Progress条 | ✅ |
| 暂停/恢复 | UI已设计 | ⚠️ 后端未完整实现 |
| SSE实时推送 | 后端有SSE端点 | ⚠️ 前端未消费 |
| 产品文档对标 | 18个状态的状态机 | ⚠️ 代码状态不完整 |

**行为洞察：**
- 工作流页面是用户**等待生成时高频刷新**的页面，但目前使用**硬编码模拟数据**。
- 缺少：步骤输出查看、审核报告查看、失败重试按钮、Token消耗展示。
- 产品文档定义了完整的七步状态机（WAITING→PLANNING→PLANNED→WRITING→...→COMPLETED），但前端Workflow页面仅处理了10个状态。

#### 阶段 7：资产管理与质量体系

| 模块 | 现状 | 评估 |
|------|------|------|
| 角色管理 | CRUD + 弹窗表单 | ✅ 基本可用 |
| 组织管理 | CRUD | ✅ 基本可用 |
| 伏笔管理 | 表格+时间线+统计卡片 | ✅ 体验较好 |
| Hook管理 | 纯表格 | ⚠️ 缺少时间线和评分 |
| 关系图谱 | 产品文档定义 | ❌ 未实现 |
| 剧情质量中心 | 产品文档定义 | ❌ 未实现 |

**亮点：** 伏笔管理页面是体验最好的之一——有时间线视图、统计卡片、进度条和状态标签，体现了对长篇创作中伏笔追踪的理解。

**缺失：** 
- Hook管理过于简单，缺少Hook强度评分、时间线、未兑现Hook提醒。
- **剧情质量中心是产品文档定义的核心差异化功能**(融合DeepReader/DeepEditor/Auditor)，但代码中完全未涉及。

## 三、关键交互模式分析

### 3.1 信息架构问题

```
当前导航（4项）：
工作台 / 项目管理 / 知识库 / 系统设置
    ↑ 过于扁平，创作核心入口全部藏在项目内部

理想导航（参考产品文档）：
工作台 → 项目管理(含详细Tabs) → 创作中心(世界/大纲/卷纲/章纲/章节)
→ 资产管理(角色/组织/职业/关系/伏笔/Hook) → 工作流监控 → 知识库 → 设置
```

**核心问题：** 导航层级设计导致创作功能「二次点击后才能触达」，增加了用户的使用摩擦。特别是世界设定、大纲、卷纲、章纲、章节这五个核心创作模块全部平铺在 `ProjectDetail.tsx` 的Tabs中——对于一个项目管理页面来说，这个Tabs数量（9个）已经超载。

### 3.2 操作频率分析

| 操作 | 频率 | 优先级 | 当前支持度 |
|------|------|--------|-----------|
| 新建章节+AI生成 | 每天多次 | P0 | ❌ 未实现 |
| 编辑已生成章节 | 每天多次 | P0 | ✅ 基本实现 |
| 查看/修改世界设定 | 每周几次 | P0 | ⚠️ 不完整 |
| 创建卷纲 | 每周1-2次 | P0 | ❌ 未实现AI生成 |
| 创建章纲 | 每天 | P0 | ❌ 页面都不存在 |
| 查看工作流进度 | 生成时频繁 | P0 | ⚠️ 模拟数据 |
| 审核/修订结果查看 | 每次生成后 | P1 | ❌ 未实现 |
| 角色/伏笔管理 | 每周 | P1 | ✅ 基本实现 |
| Hook管理 | 每周 | P1 | ⚠️ 较弱 |
| 模型配置切换 | 偶尔 | P2 | ❌ 未实现 |

### 3.3 用户心智模型 vs 系统模型分析

**用户期望的创作流程：**
```
灵感 → 设定 → 开写 → AI辅助 → 修稿 → 发布
|—— 人主导 ——|—— AI辅助 ——|—— 人主导 ——|
```

**系统当前提供的流程：**
```
登录 → 建项目 → 填设定 → 写大纲 → 创建卷 → 创建章
→ 手动写内容 → 保存
|—— 全是手动 ——|
```

**差距：** 用户期待的「AI辅助创作」在当前版本中几乎不存在（"AI生成设定"和"启动创作流程"都是TODO状态）。当前系统本质上只是一个「小说内容的CRUD管理系统」，而不是产品文档定义的「AI工业化创作平台」。

## 四、体验痛点分级

### P0 — 阻塞性痛点（不解决则无法使用核心功能）

1. **AI生成全部为TODO状态** — 世界设定、大纲、卷纲、章纲、章节正文的AI生成均未实际对接后端，用户无法体验到核心价值。
2. **章纲管理页面缺失** — 没有章纲就无法运行七步工作流，创作流程在此断裂。
3. **工作流后端未对接** — 前端点击"启动创作流程"后无实际效果，用户无法完成「生成→审核→修订→入库」闭环。

### P1 — 严重体验问题

4. **工作台无信息量** — 没有待办、进度、统计数据，用户每次登录后不知道当前创作状态。
5. **项目详情Tabs超载** — 9个Tab平铺在一个页面，信息层级混乱，用户容易迷失。
6. **缺少创作向导** — 新用户不知道从哪开始，步骤之间缺少连贯引导。
7. **HTML预览缺失** — 编辑器预览用了`white-space: pre-wrap`，不支持富文本格式。
8. **缺少错误恢复流程** — 生成失败时用户不知道原因，也无重试机制。

### P2 — 体验优化点

9. **导航顶层缺少「创作中心」快捷入口** — 所有创作功能都在项目内，改为独立页面更合理。
10. **编辑器功能太弱** — 无Markdown渲染、无分段编辑、无字数组件暗示。
11. **Hook管理太简陋** — 缺少产品文档定义的10种Hook类型和强度评分。
12. **系统设置页面为空白** — 模型配置、Prompt工坊等核心设置项未实现。

## 五、详细体验改进建议

### 5.1 工作台重构（高优先级）

```diff
- 4个统计卡片 + 一段空文本
+ 1. 最近编辑项目快捷入口（最近3个）
+ 2. 待办事项列表（未回收伏笔数、未兑现Hook数、待审核章节数）
+ 3. 创作进度总览（总字数/目标字数、已生成章节/计划章节）
+ 4. 最近的AI调用统计（Token消耗、成本、调用次数）
+ 5. 快速创建项目的浮动按钮
+ 6. 使用动画/微交互的空状态引导
```

### 5.2 项目内导航优化（高优先级）

```diff
- ProjectDetail.tsx 的 9 个Tabs页面
+ 方案A：拆分出独立的创作中心页面 + 资产中心页面
+ 方案B：在ProjectDetail内用二级导航分两组
+   - 创作流程组：世界设定 → 大纲 → 卷纲 → 章纲 → 章节
+   - 资产管理组：角色 → 组织 → 伏笔 → Hook → 工作流
+ 方案C：Stepper式引导，按步骤走完创作流程
```

### 5.3 编辑器体验重构（高优先级）

```diff
- 纯TextArea编辑
+ 1. 左侧边栏：当前章纲/hook要求/角色出场清单
+ 2. 编辑区： 支持分段/折叠/字数实时统计
+ 3. 右侧边栏：AI辅助工具栏（一键润色/扩写/去AI味）
+ 4. 底部面板：审核结果摘要/修订建议/版本对比
+ 5. 快捷键支持：Ctrl+S 保存、Ctrl+G 生成
```

### 5.4 工作流进度体验（中优先级）

```diff
- 模拟数据表格 + 进度条
+ 1. 卡片式工作流详情，展示七步当前状态
+ 2. 实时进度动画（通过SSE推送）
+ 3. 每个步骤的可展开输出详情
+ 4. 失败时可一键"重试此步骤"
+ 5. 审核不通过时显示具体问题位置+建议
+ 6. 显示Token消耗和预估成本
```

### 5.5 伏笔/Hook管理体验（中优先级）

```diff
- 伏笔管理较好，但Hook管理过弱
+ 1. Hook管理增加：强度评分(1-10)、时间线、兑现状态机
+ 2. 章末Hook缺失红点提醒（在编辑器右上角）
+ 3. 伏笔与Hook双向关联展示
+ 4. 可视图谱：在一个时间轴上展示所有伏笔和Hook
+ 5. 章节生成时自动建议"此处可埋伏笔"
```

## 六、用户行为数据埋点建议

### 6.1 建议埋点的事件

| 事件 | 触发时机 | 分析价值 |
|------|---------|---------|

## 七、优先级路线图

### 立即修复（当前阻塞）

| # | 事项 | 影响 |
|---|------|------|
| 1 | 对接AI Gateway到前端所有"生成"按钮 | 核心价值不可用 |
| 2 | 实现章纲管理页面（至少CRUD+表格） | 七步工作流断裂 |
| 3 | 对接工作流引擎到Workflow页面 | 用户无法追踪创作进度 |
| 4 | 实现Dashboard真实数据 + 空状态引导 | 新用户留存差 |

### 短期改进（2-4周）

| # | 事项 | 目标 |
|---|------|------|
| 5 | 世界设定补齐所有字段 | 与产品文档P0功能对齐 |
| 6 | 卷纲/AI生成 + 批量模式 | 批量创作能力 |
| 7 | 编辑器左右侧边栏 + 审核面板 | 创作效率提升 |
| 8 | 伏笔/Hook关联 + 时间线可视化 | 长篇连贯性保障 |

### 中期建设（1-2个月）

## 八、总结

### 核心发现

1. **产品文档定义了远超当前实现的体验蓝图**。当前代码实现了约30%的产品功能，且集中在「资产CRUD管理」层，最核心的「AI创作」能力几乎全部未对接。

2. **用户行为模式表明：用户需要「AI辅助」而非「AI替代」**。产品设计上的人工确认原则、局部重写、审核阶梯是正确的方向，但当前的实现还未到达那个阶段。

3. **信息架构需要重构**。当前9个Tabs + 4个一级菜单的组合，既不够深（创作功能被埋没），也不够宽（核心功能散落各处）。

4. **伏笔管理和角色管理是当前体验最好的模块**，说明设计者对"长篇连续性"的痛点理解到位，可以作为体验范本推广到其他模块。

5. **工作台是用户旅程的起点，但当前是信息量最少的地方**——这个落差需要优先解决。

### 一句话总结

> 当前 `ai-novel-studio` 是一座装修精美的**空房子**——房间布局和设计理念都对了，但家具（AI创作能力）还没有搬进来。用户走进来会看到漂亮的房间结构（CRUD页面），但找不到最想要的东西（AI写小说）。
